## Demonstration Overview & Objective
This script provides a step-by-step walkthrough demonstrating the CoreBank QA Agent proof of concept. The demonstration proves how the framework converts requirements into structured tests, validates multi-layer execution, audits double-entry ledger invariants, and enforces a **`DO NOT RELEASE`** quality gate when an un-reconciled duplicate debit occurs.

---

## Demonstration Sequence (Total Duration: ~9 Minutes)

### Step 1: Context & The Core Banking Problem (1 min)
- **Action:** Open [`white-paper/CoreBank-QA-Agent-White-Paper.md`](white-paper/CoreBank-QA-Agent-White-Paper.md) Section 4 & 5.
- **Talking Points:**
  - Traditional test automation evaluates HTTP status codes or DOM elements.
  - In core banking, an HTTP 200 response does not prove that a transaction posted atomically or balanced the General Ledger.
  - A 95% pass rate can still allow a catastrophic duplicate debit to reach production.

---

### Step 2: Requirement Specification & Acceptance Criteria (1 min)
- **Action:** Open [`requirements/fund-transfer-requirement.md`](requirements/fund-transfer-requirement.md).
- **Talking Points:**
  - Review requirement `REQ-PAY-FT-001` (Domestic Fund Transfer).
  - Walk through the 12 Acceptance Criteria: authentication, account state, balance limits, daily caps, idempotency, saga reversals, and PII masking.
  - Note how the AI prompt extracts unstated ambiguities (e.g., daily limit aggregation rules).

---

### Step 3: Test Catalog & 5-Factor Risk Scoring (1.5 min)
- **Action:** Open [`tests/fund-transfer-test-catalog.md`](tests/fund-transfer-test-catalog.md) and [`config/risk-rules.json`](config/risk-rules.json).
- **Talking Points:**
  - Show the 20 structured scenarios generated by the agent.
  - Explain the 5-factor risk scoring formula:
    $$\text{RiskScore} = (F \times 0.30) + (A \times 0.20) + (S \times 0.20) + (C \times 0.15) + (R \times 0.15)$$
  - Point out critical scenarios: `TC-FT-001` (Happy Path), `TC-FT-008` (UI Debounce), `TC-FT-009` (Idempotency Replay), and `TC-FT-014` (Saga Reversal).

### Step 5: Double-Entry Ledger Reconciliation (1 min)
- **Action:** Open [`tests/reconciliation/CoreBankReconciliationEngine.ts`](tests/reconciliation/CoreBankReconciliationEngine.ts).
- **Talking Points:**
  - Show how the reconciliation engine validates that $\Delta \text{Source} = \Delta \text{Beneficiary} + \text{Fees}$.
  - Explain that any non-zero ledger variance triggers a critical accounting defect.

### Step 6: End-to-End Simulation & Duplicate Debit Detection (1.5 min)
- **Action:** Execute the prototype simulation in the terminal:
  ```bash
  npm run test:simulate
  ```

- **Observed Terminal Output:**

  - `TC-FT-009` simulates an 80ms concurrency race condition where two debits ($250.00 + $250.00 = $500.00) are posted against a single credit.
  - Net variance of -$250.00 is detected and flagged.
  - Summary: 20 tests evaluated (19 passed, 1 failed).
  - Quality Gate Decision: **`DO NOT RELEASE`**.
